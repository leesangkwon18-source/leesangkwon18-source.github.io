# 여러 AI가 칸반 보드로 협업하는 9가지 방법과, 두 AI 토론 시스템 설계

> 이 글은 두 종류의 자료를 읽고 정리한 입문 매뉴얼입니다. **확인된 것**: 칸반 협업 9가지 유형은 프로그램 설명서를 읽고 정리한 내용이고, 두 AI 토론 시스템은 설계 문서를 읽고 요약한 내용입니다. **확인하지 못한 것**: 칸반 기능을 직접 돌려 본 적은 없고, 두 AI 토론 시스템도 처음부터 끝까지 시험한 결과가 아니라 설계입니다. 시간·비용·한도 숫자는 모두 측정하지 않았습니다.

## 0. 먼저 읽기

### 0-1. 결론부터

- **칸반**은 "할 일 카드를 칸(대기, 진행, 완료)에 꽂아 두는 보드"입니다. 여러 AI가 이 보드를 같이 보고 일을 나눠 가지면 누가 무엇을 했는지 기록이 남습니다.
- 자료는 칸반 협업을 **9가지 모양(P1~P9)**으로 나눕니다. 이 글 2장의 표가 그 정리입니다.
- 자료의 사용자는 "AI 3개, 연구 대상 1~2개"라는 작은 규모였고, 그 기준 우선순위는 **P5 사람 확인 → P3 다수결 → P2 이어달리기 → P9 초안 구체화(수동) → P4 장기 일지 → P1 부채꼴 병렬 → P7 스레드별 공간 → P8 무리 농사 → P6 멘션**이었습니다. 이 순서는 설명서가 아니라 자료 작성자의 판단입니다.
- 두 AI가 서로 독립적으로 분석하고, 서로 비판하고, 고치고, 하나로 종합하는 **7장 카드 토론**을 3장에서 요약합니다.
- 가장 중요한 습관 한 가지: **"두 AI가 동의했다"와 "사실로 확인됐다"는 다릅니다.** 이 매뉴얼은 두 가지를 따로 적도록 권합니다.

### 0-2. 표시 방법

자료는 문장마다 근거의 종류를 표시했습니다. 이 글도 같은 방식을 씁니다.

| 표시 | 뜻 |
|---|---|
| [확인] | 설명서나 문서에서 직접 읽은 내용 |
| [판단] | 자료 작성자의 평가나 의견 (틀릴 수 있음) |
| [설계] | 실제로 해 보지 않은 예시나 계획 |
| 추정 | 이 글이 자료를 바탕으로 짐작한 것 |
| 미확인 | 자료로는 확인이 안 되는 것 |

### 0-3. 이 글에서 바꿔 쓴 말

개인정보와 비밀 보호를 위해 아래처럼 바꿨습니다. 실제 값은 이 글에 없습니다.

| 이 글의 표현 | 실제로는 |
|---|---|
| AI-가, AI-나 | 자료에 나오는 두 AI(서로 다른 회사 모델). AI-가는 진행과 종합을 맡고, AI-나는 반대편 분석과 계산 재현을 맡습니다. |
| 진행 AI | 자료 준비·진행·종합을 맡은 AI |
| 상시 서버 | 항상 켜 두는 작은 컴퓨터 |
| 스마트폰 시험 기기 | 자료에서 설명서를 읽고 정리할 때 쓴 기기 |
| 대괄호 [  ] | 복사해서 쓰는 말에서 직접 채울 부분 |

종목 이름, 계정, 비밀번호, 키, 주소 등은 쓰지 않았습니다. 자료에 주식 예시가 있지만 **이 글은 투자 조언이 아니며**, 구조를 설명하는 데만 썼습니다.

### 0-4. 어려운 말 풀이

| 용어 | 한 줄 풀이 |
|---|---|
| 에이전트 | 일을 맡아 스스로 도구를 쓰며 처리하는 AI 한 명 |
| 칸반 | 카드를 칸에 꽂아 진행을 보는 할 일 보드 |
| 카드 | 보드 위의 일감 한 건 |
| 프로필 | 이름과 기억, 역할 설명을 가진 AI 일꾼 한 명분의 설정 |
| 디스패처 | 카드를 일꾼에게 나눠 주는 배정 담당 프로그램 |
| 독립 분석 | 서로의 답을 보지 않고 각자 따로 하는 분석 |
| 교차검증 | 한쪽 결과를 다른 쪽이 검사하는 것 |
| 원출처 | 공시·원문처럼 정보가 처음 나온 자료 |
| 앵커링 | 먼저 본 의견에 생각이 끌려가는 현상 |
| 아첨 | AI가 상대나 사용자에게 맞춰 주느라 틀린 말에 동의하는 현상 |

## 1. 칸반 협업이란

### 1-1. 기존 방식과 비교

자료는 지금까지의 방식(진행 AI가 임시 하위 AI에게 심부름을 시키고 결과를 받는 방식)과 칸반을 이렇게 비교합니다. [확인: 설명서 비교표 + 판단]

| | 심부름 방식 (지금) | 칸반 |
|---|---|---|
| 모양 | 진행 AI가 시키고 결과를 받음 | 모두가 보는 공유 업무 게시판 |
| 일꾼 | 임시 하위 AI | 이름과 기억이 있는 프로필 |
| 기록 | 최종 요약만 돌아옴 | 카드와 인계 내용이 데이터베이스에 남음 |
| 사람 개입 | 설명서상 "지원 안 됨" | 댓글, 해제로 언제든 가능 |
| 실패했을 때 | 끝나면 사라짐 | 재시도, 차단기 |
| 설정 난이도 | 낮음 | 높음 (프로필, 디스패처 등) |

### 1-2. 장점과 대가

- 장점 [판단]: 기록이 남고, 사람이 중간에 끼어들 수 있고, 실패한 일감만 따로 다시 할 수 있습니다.
- 대가 [판단]: 설정이 어렵고, 일꾼 프로필마다 준비가 필요하며, 상시 켜 둔 기기가 있어야 합니다.
- 자료는 **칸반이 분석 품질이나 결과를 높인다는 실험 근거는 찾지 못했다**고 적었습니다. 칸반은 "일을 정리하는 도구"이지 "답을 더 맞게 만드는 마법"이 아닙니다.

### 1-3. 실제로 해 본 것과 안 해 본 것

- 자료 1(P1~P9 정리)은 설명서를 읽고 쓴 것입니다. **칸반을 직접 돌려 본 것은 아닙니다.**
- 자료 2(두 AI 토론 설계)는 "기존 7장 카드 토론을 과거에 한 번 돌려 본 사례"를 바탕으로 합니다. 과거 사례 시간이 약 10분이었다는 기록이 있습니다. [확인] 다만 새 질문에서의 시간은 미정입니다.
- 설명서 자체의 불일치: 본문은 "8가지 패턴"이라고 쓰지만 표에는 P1~P9로 9개가 있어, 자료는 표 기준으로 9개로 셌습니다. [확인]

## 2. 패턴 P1~P9

### 2-1. 한눈에 보는 표

| 유형 | 한 줄 | 방향 | 주 용도 |
|---|---|---|---|
| P1 부채꼴 병렬 | 한 일을 주제별로 쪼개 동시에 조사 | 병렬 | 큰 조사 |
| P2 이어달리기 | 앞 결과가 뒤로 넘어가며 검증 | 직렬 | 단계가 있는 일 |
| P3 다수결 | 같은 질문에 독립 답을 받고 취합 | 교차검증 | 틀리면 비싼 판단 |
| P4 장기 일지 | 같은 담당이 같은 폴더에 기록을 쌓음 | 시간 | 반복 관찰 |
| P5 사람 확인 | 애매하면 멈추고 사람에게 묻기 | 안전장치 | 되돌리기 어려운 결정 |
| P6 멘션 | 글 속에서 담당자를 불러냄 | 호출 | 동작 미확인 |
| P7 스레드별 공간 | 대화방 주제마다 업무를 분리 | 주제 | 여러 프로젝트 |
| P8 무리 농사 | 같은 종류 일감을 줄지어 처리 | 대량 | 반복 업무 |
| P9 초안 구체화 | 거친 한 줄을 업무로 다듬거나 쪼갬 | 접수 | 모호한 요청 |

아래 설명에서 "장점, 단점"은 모두 [판단](자료 작성자 의견)입니다.

### 2-2. 패턴별 설명

#### P1. 부채꼴 병렬 (한 일을 쪼개 동시에)

- **언제 쓰나**: 서로 상관없는 조사가 여럿일 때. 예: 한 대상을 재무, 뉴스, 업황, 위험으로 나눠 조사 [설계].
- **알아 둘 점** [확인]: 같은 줄의 카드끼리는 서로의 내용을 볼 수 없습니다. 그래서 "나누기 전에 결정하라"는 규칙이 있습니다. 기준 날짜, 출처 표기, 숫자 단위 같은 공통 선택은 나누는 쪽이 먼저 정해 모든 카드 본문에 똑같이 적습니다.
- **장점**: 빠릅니다(가장 느린 카드 한 장의 시간). 관점이 넓어지고 카드별 기록이 남습니다.
- **단점**: 결과끼리 모순될 수 있고, 주제를 빠뜨리면 빈틈이 생깁니다. 합치는 한 명이 병목이 됩니다. 같은 근거를 읽으면 같이 틀립니다.
- 주고받는 토론에는 맞지 않습니다.

#### P2. 이어달리기 (앞 사람이 끝나야 다음 사람)

- **언제 쓰나**: 정찰, 편집, 작성처럼 단계가 있는 일. 예: 수집, 분석, 반대 검토, 정리, 사용자 결정 [설계].
- **알아 둘 점** [확인]: 앞 카드가 끝나야 뒤 카드가 시작되고, 앞 카드의 요약이 뒤 카드 일꾼에게 그대로 전달됩니다. 검토 요청, 수정 요청, 재요청, 승인 흐름이 기록으로 남습니다. 끝난 카드는 다시 열지 않고 새 카드로 후속 처리합니다.
- **장점**: 책임이 분명하고, 되돌려 검증하기 쉽고, 나중에 기록을 감사할 수 있습니다.
- **단점**: 앞 단계의 오류가 뒤로 퍼지고, 한 단계가 막히면 전체가 멈춥니다. 인계 요약이 부실하면 정보가 사라집니다.
- 설명서 사례 [확인]: 기획, 구현, 검토(1차 반려 후 수정).

#### P3. 다수결 (같은 질문, 따로 답한 뒤 취합)

- **언제 쓰나**: 틀리면 비싼 판단. 예: 같은 질문 "가장 큰 위험 3가지와 근거 링크"를 세 AI가 따로 답하고, 취합자가 표로 비교(셋 다 지적한 것, 한 명만 지적한 것, 숫자가 어긋난 것으로 구분) [설계].
- **알아 둘 점** [확인/판단]: 득표를 세어 주는 별도 기능은 없습니다. 취합 카드를 여러 부모 카드에 연결하는 조합 방식입니다. 득표 규칙, 일부가 실패했을 때의 처리는 자료로 확인하지 못했습니다(미확인).
- **장점**: 의견이 갈린 곳이 드러납니다. 서로 다른 회사 모델이면 약점이 서로 상쇄될 수 있습니다.
- **단점**: 다수결이 정답을 보장하지 않습니다. 같은 자료를 읽으면 독립이 아닙니다. 시간과 비용이 사람 수만큼 늘어납니다.
- 참고: AI가 둘뿐이면 "다수결"이 아니라 "쟁점 발견 도구"입니다. [판단]

#### P4. 장기 일지 (같은 담당이 기록을 계속 쌓음)

- **언제 쓰나**: 매일, 매주 같은 대상을 관찰할 때. 예: 매일 아침 어제 기록을 읽고 오늘 변화를 덧붙임, 주 1회 다른 AI가 검토 [설계].
- **알아 둘 점** [확인]: 작업 폴더를 절대 경로로 지정하면 일이 끝나도 보존됩니다(임시 작업 공간은 끝나면 삭제). 프로필의 기억이 쌓입니다. 설명서의 신뢰 모델은 "내 기기, 내 권한"으로 개인용 설계입니다.
- **장점**: 맥락이 쌓이고, 파일이라 사람이 읽고 고칠 수 있고, 나중에 비교하기 쉽습니다.
- **단점**: 틀린 기록도 같이 쌓입니다. 길어지면 읽는 비용이 늘고, 기기가 꺼지면 빈 날이 생깁니다. 민감한 정보가 한곳에 모입니다. AI 모델이 스스로 학습하는 것은 아닙니다.
- 필요한 규칙 [설계]: "출처 링크가 없는 기록은 쌓지 않는다".

#### P5. 사람 확인 (애매하면 멈추고 묻기)

- **언제 쓰나**: 되돌리기 어렵거나 애매한 결정.
- **알아 둘 점** [확인]: 작업자가 "막힘"으로 멈추면 사용자가 댓글로 답하고 해제합니다. 막힘에는 네 종류가 있고(의존, 입력 필요, 능력 부족, 일시적), 뒤 셋은 사람에게 올라갑니다. 같은 이유로 반복해서(기본 2회) 막히면 자동으로 접수 단계로 되돌아갑니다. 심부름 방식은 사람 개입이 "지원 안 됨"이지만 칸반은 "언제든 댓글, 해제"입니다.
- **장점**: AI가 애매한 결정을 마음대로 하지 않고, 책임이 사람에게 남고, AI의 "모르겠다"가 드러납니다.
- **단점**: 사람이 답할 때까지 멈추고, 알림이 누락될 수 있고, 너무 자주 물으면 형식적인 승인이 됩니다. 무엇을 반드시 물을지 기준이 필요합니다.
- 자료의 권고 [설계]: "의견이 갈린 쟁점", "출처마다 숫자가 다름", "사용자 판단 필요" 항목에서는 반드시 멈추도록 지침에 고정.
- **초보자에게 가장 추천되는 유형**입니다(자료 우선순위 1위, [판단]).

#### P6. 멘션 (글 속에서 담당자 부르기)

- **언제 쓰나**: 설명서에는 표 한 줄뿐이라 **동작을 확인하지 못했습니다(미확인)**. 이하는 추정입니다.
- 자료가 확인한 것: 칸반 문서의 "멘션"은 보드 간 카드를 연결할 수 없을 때 "자유 텍스트로 적고 번호로 직접 찾기"라는 임시 방편입니다. 메신저의 "@로 부를 때만 응답" 설정은 칸반 P6와 별개 기능입니다. [확인]
- 단점 [판단]: 이름 오타는 조용히 무시될 수 있고, 호출이 늘어 비용이 커집니다.
- 자료 사례 [확인]: 어떤 서버 봇에서 AI를 부르는 말이 모델 전환 명령으로 처리된 적이 있습니다(원인 미확정).
- 권고 [판단]: 우선순위 최하위. 쓴다면 "사용자 승인 후 호출".

#### P7. 스레드별 작업 공간 (대화방 주제마다 업무 분리)

- 설명서에 표 한 줄뿐이라 **정확한 동작은 미확인**입니다.
- 관련 사실 [확인]: 칸반 보드는 보드마다 따로 데이터베이스, 폴더, 로그를 갖는 강한 분리입니다. 메신저의 "주제"별 대화는 주제마다 세션이 분리됩니다(해당 설정을 켜야 함).
- 장점 [판단]: 주제별 기록이 분리되고 대화가 짧아져 느려짐이 줄어듭니다.
- 단점 [판단]: 지원하는 플랫폼이 필요하고, 방이 많아지면 관리가 복잡하고, 주제 간 비교가 불편합니다.
- 권고 [판단]: 연구 대상이 한두 개면 칸반 없이 메신저 주제 기능만으로 먼저 시험. 같은 봇 연결 정보를 두 곳에서 쓰지 말 것.

#### P8. 무리 농사 (같은 종류 일감을 줄줄이)

- **언제 쓰나**: 같은 점검을 대상 수십 개에 반복할 때. 설명서 예시: "소셜 계정 50개, 모니터링 서비스 12개". 자료는 칸반이 "원래 가장 최적화한 사용법"이라고 적었습니다. [확인]
- **알아 둘 점** [확인]: 일감이 일꾼보다 많으면 대기하다 자동 시작합니다. 배정 담당(디스패처)이 기본 60초 간격으로 일을 나눠 줍니다. 사업별 구분 표시는 약한 필터입니다. 게이트웨이(연결 창구)가 여럿이면 디스패처는 한 곳에서만 돌려야 합니다.
- **장점**: 반복 업무를 자동으로 소화하고, 일감 단위로 실패가 격리됩니다.
- **단점**: 일감이 서로 독립일 때만 맞고, 대상이 적으면 이점이 없습니다. 지침이 틀리면 오류가 대량 복제되고, 비용이 급증할 수 있습니다.
- 자료의 판단 [판단]: 연구 대상 20개쯤이면 의미가 있지만 1~2개면 과합니다.

#### P9. 초안 구체화 (거친 한 줄을 업무로)

- **언제 쓰나**: "요즘 괜찮아?" 같은 모호한 요청을 받았을 때.
- **알아 둘 점** [확인]: 거친 아이디어가 접수 칸에 들어오면 (1) 한 카드의 본문을 구체적으로 다시 쓰거나(Specify), (2) 여러 자식 카드로 쪼개 전문가에게 배정합니다(Decompose). 자동 모드와 수동 모드가 있고, 담당자는 각 프로필의 "설명"을 보고 고릅니다.
- **장점** [판단]: 비전문가의 진입 장벽이 낮아지고 빠뜨린 관점을 보완합니다. 수동 모드로 통제할 수 있습니다.
- **단점** [판단]: AI가 의도를 넓게 해석할 수 있고, 자동 모드는 호출 수와 비용이 늘고, 분해 결과를 되돌리기 어렵습니다.
- 자료의 권고 [설계]: 수동 모드와 사용자 승인. 지침에 "자동매매·증권사 계정 연결 금지", "투자 조언 아님"을 고정.
- 이미 하는 것 [확인]: 사람이 AI와 대화하며 거친 요청의 용어를 풀고 형식을 정하는 것이 사실상 Specify입니다.

### 2-3. 공통 한계

- 칸반이 분석 품질을 높인다는 실험 근거는 찾지 못했습니다. [확인]
- P6, P7은 설명이 표 한 줄뿐이고, P3, P4도 설명이 짧아 동작이 확인되지 않았습니다. [확인]
- 각 패턴의 "설계" 사례는 검증되지 않은 예시입니다.
- 스마트폰 시험 기기는 켜 두는 시험 중이었으므로 자료는 칸반 도입을 시험 종료 후 상시 서버에서 검토하라고 권했습니다. [판단]

## 3. 두 AI 토론 시스템 설계 요약

> 이 장은 **설계 문서의 요약**입니다. 문서 스스로 "설계 검토 결과이며 처음부터 끝까지 시험한 보고가 아니다"라고 밝힙니다. 아래 합격 조건은 앞으로 시험할 체크리스트입니다.

### 3-1. 기본 생각

- **지금 있는 것만 씁니다.** 새 서버, 예약 실행, 새 메신저, 유료 서비스는 필요 없다는 설계입니다.
- 목표는 "정답을 맞히는 AI"가 아니라 **"근거, 반증, 미검증, 사람이 정할 질문"을 내놓는 것**입니다.
- 최종 결정은 **사용자**가 합니다. 사용자가 답하기 전의 결정은 "미정"입니다.

### 3-2. 세 가지 형식

| 형식 | 언제 | 무엇을 하나 | 승인 |
|---|---|---|---|
| A. 빠른확인 (1~3분, 계획치, 미측정) | 가볍고 되돌리기 쉬운 질문 | 진행 AI가 먼저 답을 확정, 필요하면 독립된 맥락에서 1회 점검, 비교 | 불필요 |
| B. 정식 토론 (과거 한 사례 약 10분 [확인], 새 질문은 미정) | 판단이 갈리고 중요한 질문 | 7장 카드: 독립 분석, 상호 비판, 수정, 종합 | 사용자가 요청하면 불필요 |
| C. 정기 점검 (설계만) | 같은 확인을 반복할 때 | 승인된 명세로 "변화 감시"만 함. 토론은 자동으로 시작하지 않음 | 필요 |

말투 예시(설치된 명령어가 아니라 평범한 한국어로 써도 됩니다): `빠른확인: …`, `풀토론: …`, `기록: …`

### 3-3. 핵심 원칙 5개

1. 현재 수치는 AI의 기억이 아니라 **원출처(공시 등)**로 확인합니다.
2. 두 AI가 동의해도 "확인됨"이 아닙니다. **합의와 검증을 따로 표시**합니다.
3. 반대 의견 개수를 억지로 채우지 않습니다. **반례, 반증 조건, 증거 공백**을 찾게 합니다.
4. 최종 결정은 사용자입니다.
5. 못 한 것은 못 했다고 씁니다(임시본은 정식이 아니고, 미검증은 확인이 아닙니다).

### 3-4. B 정식 토론의 7장 카드

| 번호 | 담당 | 내용 | 먼저 끝나야 하는 것 |
|---|---|---|---|
| 준비 | AI-가 | 자료 묶음: 질문, 제외 범위, 기준 시각, 핵심 원문 3~5개, 위치, 정정 여부, 확보 실패 자료 | 없음 |
| 1 | AI-가 | 독립 분석 | 준비 |
| 2 | AI-나 | 독립 분석 (1번 결론은 받지 않음) | 준비 |
| 3 | AI-가 | 2번 전체를 읽고 비판 | 1, 2 |
| 4 | AI-나 | 1번 전체를 읽고 비판 | 1, 2 |
| 5 | AI-가 | 수정 + "수용/부분/거절" 표 | 1, 4 |
| 6 | AI-나 | 수정 + "수용/부분/거절" 표 | 2, 3 |
| 7 | AI-가 | 종합 | 5, 6 |

핵심 규칙:

- "준비"는 보통 접수할 때 만드는 **첨부 파일**이라 카드 수는 7로 유지합니다. 카드로 만들면 "준비 1 + 분석 7"이라고 밝힙니다.
- 후속 카드는 요약이 아니라 **앞 카드의 전문**을 읽습니다.
- 비판과 수정은 **1라운드**만. 추가 라운드는 사용자 승인이 필요합니다.
- 7번 종합 맨 위에 "종합자는 분석 당사자이며 독립 제3자 검증이 아님"을 적습니다.
- 종합이 상대 의견을 왜곡하지 못하도록, 상대의 핵심 문장을 **원문 그대로 인용**하고 소수 의견을 상대의 표현으로 적습니다.
- 선택 확장(B8): 제3자가 종합의 왜곡을 점검. **승인이 필요**하고 기본 예산과 분리합니다.
- 글이 완성된 것과 사실이 검증된 것은 다릅니다. 핵심 자료가 없으면 "토론 문서 완료 / 사실 검증 미완료 / 판단 보류"로 표시합니다.

### 3-5. A 빠른확인 규칙

1. 진행 AI가 질문, 기준 시각, 자료 범위를 고정하고 **자기 답을 먼저 저장**합니다(이후 수정 금지).
2. 판단이나 수치에 관한 질문이면 독립된 맥락에서 1회 점검하는 것이 기본입니다. 점검자에게는 **중립 질문과 원자료만** 주고, 진행 AI의 결론과 사용자의 기대는 숨깁니다.
3. 점검 결과의 첫 줄에 "실제 검토 주체: 확인된 모델 또는 미확인"을 적습니다. 점검 AI가 스스로 이름을 말하는 것만으로는 확인이 아닙니다.
4. 결과는 턴이 끝난 뒤 비동기로 도착합니다. 도착 전 결과를 지어내지 않습니다.
5. 핵심 원문을 확인하지 못했으면 가벼운 질문이라도 확정 답 대신 "미검증"으로 답합니다.
6. 점검을 못 했으면 "단독검토 — 교차검토 미완료"로 표시하고, 사용자가 미리 허용하지 않았다면 추가 호출 전에 사용자에게 묻습니다.

### 3-6. C 정기 점검 규칙 (설계만, 아직 등록 금지)

- 처음에는 **한 가지만**: 신규 공시 목록, 기존 근거 공시의 정정, 실적 발표 일정 변경 중 하나.
- 결과는 "변화 없음 / 새 자료 있음 / 확인 실패" 셋 중 하나이며 **"확인 실패"를 "변화 없음"으로 쓰지 않습니다.**
- 새 변화가 있어도 토론을 자동 시작하지 않고 "토론 제안"만 보냅니다.
- 선행 조건: 같은 감시를 먼저 수동으로 돌려 자료 접근을 시험. 등록 전 승인 항목: 소유 기기, 일정, 출처, 실행 상한, 결과를 받을 방, 중단 조건, 모델.
- 실시간 경보가 아닙니다. 중복 방지 장치는 앞으로 구현하고 시험해야 할 약속이며 **현재는 보장되지 않습니다.**

### 3-7. 편향 방지 장치

| 문제 | 설계 속 대응 |
|---|---|
| 앵커링 (먼저 본 의견에 끌림) | 독립 분석 카드는 상대 카드에 의존하지 않고 같은 중립 자료만 받음. 교차 열람은 초안 확정 후. 질문은 중립으로(보유 여부, 희망 가격, 진행 AI의 가설 금지). "상대 원문 노출 여부: 없음/있음/미확인"을 기록. 노출 가능성이 있으면 "완전 독립 미충족"으로 표시하고 "안 봤다"고 나중에 우기지 않음 |
| 아첨 (상대에게 맞춰 줌) | 비판 카드는 "가장 강한 반례, 반증 조건, 증거 공백, 반론 없음의 이유" 중 해당 칸을 씀. 최소 반대 개수는 없음. 수정 카드는 비판마다 수용/부분/거절과 한 줄 근거를 적음. 전부 수용도 근거가 있으면 정당함 |
| 둘 다 같이 틀림 | 모든 수치에 "검증됨(출처, 위치, 확인일)" 또는 "미검증" 태그를 붙임. 태그 없는 수치는 무효. 주장을 사실, 가정, 해석, 미확인으로 구분. 같은 보도자료를 베낀 기사 여럿은 독립 근거 1개로 셈 |
| 자료 속 명령문 | 문서와 웹페이지 속 명령은 연구 자료일 뿐 지시가 아님. 계정 연결, 외부 전송, 코드 실행, 결제는 사용자 명시 승인 없이는 하지 않음 |
| 의견이 갈림 | "의견 A / 의견 B / 갈린 이유"로 보존하고 "양쪽 합의"로 뭉개지 않음 |

사용자의 "이건 왜?"라는 질문이 마지막 방어선이라고 설계는 적고 있습니다.

### 3-8. 의사결정 메모 양식 (설계의 양식을 줄여 옮김)

```text
상태: 확인 완료 / 부분 확인 / 판단 보류
실제 검토 주체: (확인값 또는 미확인)
정식 7카드: 완료 / 미완료(임시본)
상대 원문 노출 여부: 없음 / 있음 / 미확인
질문 · 자료 기준 시각:
확인한 사실(출처, 위치):
같은 생각 / 다른 생각(소수 의견) / 아직 모름:
결론이 바뀌는 조건 · 다음에 확인할 사건:
사람이 정할 질문 2~3개:
사용자 선택: 미정
```

- 정본은 해당 건의 종합 카드에 붙인 기록 파일이며, 수정은 덮어쓰지 않고 새 버전으로 추가합니다.
- 사용자가 **직접 말한** 선택만 기록하고, AI가 추정해서 대신 적지 않습니다.
- 계좌, 자산 세부, 개인 식별 정보, 토큰은 기록하지 않습니다.

### 3-9. 한도와 실패 대응

| 상황 | 대응 |
|---|---|
| 한쪽 AI가 사용 한도에 걸림, 재개 시각을 앎 | 시각을 기록하고 그 AI에 의존하는 카드는 대기. 이미 끝난 결과는 보존 |
| 한도에 걸렸고 재개 시각을 모름 | 재시도하지 않고 멈춰서 선택을 요청: 대기 / 단일 AI 임시본 / 취소 |
| 한쪽 카드만 끝남 | "단일 AI 임시본(교차검증 안 됨)"으로만 제공. 정식 종합을 강제로 완료 표시하지 않음 |
| 자료에 접근 불가 | 해당 수치는 미검증. 공개 대체 자료나 사용자가 준 원문을 요청. 접근 통제 우회와 유료 결제는 안 함 |
| 두 AI가 같은 오류 | 원문으로 돌아가 정정 버전을 연결하고 규칙을 한 줄 추가 |
| 기기가 꺼짐, 무응답 | 작업 번호, 상태, 마지막 첨부부터 확인. 돌고 있는 작업을 다른 기기에서 중복 시작하지 않음 |
| 전달 확인 불가 | 수신 확인 전에 성공이라 하지 않고, 같은 내용을 맹목적으로 다시 보내지 않음 |

한도를 피하려고 다른 계정, 모델, 서버로 옮기는 것은 하지 않습니다. 재시도는 최대 1회가 제안되지만 이는 근거 없는 운영 상한일 뿐입니다. [제안]

### 3-10. 승인이 필요한 것

| 항목 | 승인 |
|---|---|
| 사용자가 요청한 A, B 실행과 그 범위의 메모, 첨부 | 불필요 |
| 방 연결 읽기 전용 점검 | 불필요 |
| 제3자 점검(B8), 추가 비판 라운드, 추가 조사 | 필요 |
| 예약 실행 생성, 수정, 재개, 자동 토론 | 필요 |
| 누적 로그 위치 신설, 노트 앱 연동, 외부 공유 | 필요 |
| 새 프로필, 스킬 | 필요 |
| 연결 창구, 알림 구독, 방 설정, 디스패처 소유권 변경 | 필요 |
| 모델 고정, 제공자 변경, 한도 증액, 유료 API, 구독 결제, 서버 이전 | 필요 |
| 증권 계좌 연결, 자동매매 | 이 설계 범위 밖. 하지 않음 |

"아무 승인도 필요 없다"는 뜻이 아닙니다. 조사 요청의 범위와 권한은 항상 사용자가 정합니다.

### 3-11. 시간과 비용

- 전부 **미측정**입니다. 1~3분, 15~30분, 10~20분 같은 숫자는 계획치이거나 근거 없는 추정으로 자료가 직접 표시했습니다. 약 10분은 과거 한 사례일 뿐입니다.
- 카드 수와 AI 호출 수는 같지 않습니다. 구독형이라도 "무료"가 아닙니다. 가격과 한도는 자료가 채우지 않았습니다.
- 병렬 실행은 해당 서버에서 확인되지 않아, 직렬이면 시간이 합산됩니다.

### 3-12. 설계 문서가 자기 한계로 적은 것

- 독립성은 불완전합니다. 같은 지시문, 도구, 인터넷을 쓰고, 보드의 요약이나 공유 기억으로 상대 내용이 새어 들어갈 수 있습니다. 종합을 맡은 AI의 영향은 줄어들 뿐 사라지지 않습니다.
- 토론은 판단의 질을 높일 수 있어도 **시장 예측 정확도를 보장하지 않습니다.**

### 3-13. 보조 자료(B7 종합)에서 읽은 것

보조로 읽은 "두 AI 독립 분석 후 상호 비판이 한 AI 단독 분석보다 나은가"에 대한 종합 보고서(앞부분)의 내용입니다. 영어 문서이며 앞 8KB(약 90줄)만 읽었습니다.

- 양쪽이 공통으로 내린 결론 [개념적 추론, 측정 아님]: 이 방식은 **오류를 찾아내고 빈틈을 줄이는 작업 방식이지 진실의 원천이 아닙니다.**
- 따로 쓴 두 문서(분리된 맥락)도 같은 학습 자료, 지시문, 출처, 도구를 공유하면 같이 틀릴 수 있습니다.
- 동의는 약한 증거입니다. 둘 다 빠뜨린 것은 동의로는 드러나지 않습니다. 의견 불일치는 "어디를 더 볼지" 알려 주는 표지입니다.
- 비교 기준은 "한 번 답한 AI"가 아니라 "스스로 점검하고 도구도 쓰는 강한 단일 AI"여야 공정합니다.
- 비판이 오히려 오류를 만들 수 있으므로(거짓 지적, 비위 맞추기) "고칠 것 없음"도 정상 결과로 허용해야 합니다.
- 종합 단계도 실패 지점입니다. 중립적인 종합자도 정답을 아는 존재가 아닙니다.
- 비용 배수(3~4배 등)는 근거가 없어 양쪽이 모두 철회했습니다. 측정하지 않았다는 점이 열린 문제로 남았습니다.
- 이 보고서의 원 과정은 질문 1개, AI 한 쌍, 1회 실행이라 효과 크기를 말할 수 없다고 스스로 적었습니다.

## 4. 시작하는 순서 (처음 하는 사람용)

아래는 두 자료를 바탕으로 이 글이 정리한 순서입니다. 설계 문서의 단계(0~4단계)와 P 패턴 권고를 합친 것이며, **끝까지 실제로 시험해 본 순서는 아닙니다.**

1. **칸반 없이 시작합니다.** 자료는 대상이 한두 개면 칸반 없이 대화만으로 먼저 시험하라고 권합니다(P7 권고). 칸반 도입은 상시 켜 둘 기기에서 검토하라고 했습니다.
2. **0단계: 연결 점검 (읽기 전용).** 결과를 받을 대화방이 어느 AI 프로필, 보드와 연결돼 있는지만 확인하고, 변경이 필요하면 하지 말고 먼저 승인을 받습니다. 같은 작업을 다른 기기에서 또 켜지 않습니다.
3. **1단계: 수동으로 3~5회.** A 빠른확인과 B 정식 토론을 직접 써 보며 매번 기록합니다. 단계별 시간, 실제 모델, 확인 가능한 사용량, 장애, 방에 전달됐는지. 이 기록이 이후 예산의 근거가 됩니다(지금은 모두 미측정).
4. **2단계: 승인 후** 영구 로그 위치, 템플릿 스킬.
5. **3단계: 승인 후** 주 1회 변화 감시 1개를 2주 시험하고 유지 또는 중단을 판단합니다(주 1회는 예시이고 조정 가능).
6. **4단계: 선택.** 외부 임대 서버(VPS)는 **실제 가용성 문제가 관찰된 뒤에만** 논의합니다.

자료 기준 시각을 먼저 밝히고, 핵심 공시 3~5개는 원문으로 확인해. 비판과 수정은 한 번만.

합의된 것 중 아직 원문 확인 안 된 것도 따로 보여줘.

## 확인하지 못한 것 (미확인)

- 칸반 기능을 직접 돌려 본 결과는 없습니다. P1~P9는 설명서를 읽은 정리입니다.
- 설명서의 "8가지 패턴"이라는 본문과 표 9개의 불일치 이유는 확인하지 못했습니다.
- P6 멘션, P7 스레드별 공간의 실제 동작. P3의 득표 규칙, 일부 실패 시 처리, P8 차단기의 세부.
- 칸반이 분석 품질을 높이는지에 대한 근거.
- 설계 속 주식 방의 연결 상태, 알림이 실제로 도착하는지.
- 위임된 점검 AI가 실제로 어느 모델로 돌았는지(현재 시점 재확인 안 됨), 프로필 병렬 실행 여부.
- 사용 한도, 잔여량, 리셋 시각, 모든 금액, 구독 비용.
- 공시·통계 사이트 등 외부 자료원의 현재 접근성, 이용 조건, 요금.
- 예약 실행의 실제 설치 상태, 소유 기기, 제한 시간, 재시도, 실제 동작. 중복 방지 장치의 실제 보장 여부.
- 시간 수치(1~3분, 10분, 15~30분 등)는 새 질문에서 측정한 적이 없습니다.
- 종합 보고서의 인용 논문 4편은 직접 확인되지 않았고 보고서가 말한 내용만 있습니다. 이 글은 논문 내용을 사실로 쓰지 않았습니다.
- 두 AI 토론이 한 AI 단독 분석보다 실제로 낫다는 측정 결과는 없습니다.

## 한 줄 정리

**칸반은 여러 AI의 일을 기록으로 남기는 보드이고, 처음에는 "사람 확인(P5) + 다수결(P3) + 이어달리기(P2)"만 이해하면 충분하며, 두 AI가 동의했더라도 원출처로 확인되기 전에는 "확인됨"이라고 쓰지 않는 것이 이 모든 설계의 핵심입니다.** 이 글의 모든 내용은 일반 정보이며 투자 조언이 아닙니다.
