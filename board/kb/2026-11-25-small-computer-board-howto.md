# 작은 컴퓨터에 승인제 홈페이지와 회원 게시판 직접 만들기

> 이 글은 2026년 11월 24일 하루 동안, 남는 서버용 컴퓨터 한 대에 **홈페이지와 승인제 게시판**을 직접 만들고 시험한 기록을 초보자용으로 정리한 것입니다.
>
> **먼저 결론입니다.** 외부 프로그램을 하나도 설치하지 않고(파이썬 기본 기능만 사용) 홈페이지, 회원 가입 승인, 글쓰기, 댓글, 파일 첨부, 회원 관리까지 돌아가는 게시판을 만들 수 있었습니다. 다만 **인터넷에 공개하지는 않았고**, 컴퓨터를 껐다 켰을 때의 자동 시작과 실제 사용자가 많을 때의 성능은 **확인하지 못했습니다.** 서버 주소·계정 이름 같은 개인 정보는 `<…>` 자리표시자로 바꾸었습니다.

## 0. 먼저 읽기

### 이 글이 다루는 것

- 어떤 홈페이지·게시판을 만들었고 **왜 그렇게 정했는지**
- 서버에서 **안전하게 따로 돌리는 방법**(전용 계정, 자동 시작)
- 게시판의 **기능**(승인제 가입, 권한 나누기, 댓글, 첨부, 회원 관리)
- **시험한 방법과 결과**, 그리고 **확인하지 못한 것**
- 평소 **관리하는 방법**(백업, 되돌리기)

### 이 글이 다루지 않는 것

- 프로그램 코드를 한 줄씩 설명하는 것(이 글은 만드는 순서와 판단을 설명합니다)
- 인터넷에 공개하는 방법(공개는 아직 결정하지 않았습니다. 7장 참고)
- 회원의 개인 정보를 법에 맞게 다루는 방법(법령상 의무는 **확인하지 못했습니다**)

### 자리표시자

글 속의 `<웹_계정>`, `<서버_주소>` 같은 꺾쇠 표시는 **독자가 자기 값으로 바꿔 넣는 자리**입니다. 이 글에는 실제 주소나 계정을 적지 않았습니다.

## 1. 무엇을 만들었나

| 항목 | 내용 |
| --- | --- |
| 홈페이지 | 첫 화면, 메뉴, 검색창, 분야 카드, 자료실 안내 |
| 게시판 | 자유게시판 1개 + 자료실 8개 |
| 가입 | **누구나 가입 신청**은 할 수 있지만, **관리자가 승인해야 로그인**이 됩니다 |
| 권한 | 자료실은 **관리자만 글을 쓰고 누구나 읽음**, 자유게시판은 **승인된 회원이 글을 씀** |
| 기능 | 댓글, 글 수정·삭제(휴지통), 파일 첨부, 링크 자동 연결, 비밀번호 변경, 회원 관리 |
| 만든 방법 | **직접 만든 작은 파이썬 프로그램 한 개**(외부 부품 없음) |
| 글 저장 방식 | 글 하나가 **파일 하나**(마크다운 `.md`)로 저장됩니다. 데이터베이스가 없어서 백업과 옮기기가 쉽습니다 |
| 메모리 | 약 40~75MB(상한 300MB를 두었음) |

### 왜 직접 만들었나

이미 만들어진 게시판 프로그램은 대부분 크고(메모리 2GB 이상인 것도 있음) 설정이 복잡합니다. 이 컴퓨터는 **다른 일(AI 에이전트)도 하고 있어서** 가벼워야 했고, 글을 **파일 그대로 보관**하고 싶었습니다. 그래서 작은 프로그램을 직접 만드는 쪽을 골랐습니다.

## 2. 안전하게 따로 돌리기

### 2-1. 웹 전용 계정 만들기

서버에는 이미 다른 일을 하는 계정이 있었습니다. 홈페이지가 뚫려도 **그 계정의 열쇠와 로그인 정보를 읽지 못하게** 웹 전용 계정을 새로 만들었습니다.

| 설정 | 내용 |
| --- | --- |
| 관리자 권한 | **없음** |
| 비밀번호 로그인 | **잠금**(열쇠 파일로만 접속) |
| 홈 폴더 권한 | **본인만 읽기·쓰기**(700) |
| 확인한 것 | 다른 계정의 폴더를 이 계정에서 **읽으려 하면 거부**됨(확인됨) |

**알아 두실 한계:** 계정을 나누는 것은 **완전한 격리가 아닙니다.** 같은 컴퓨터를 쓰므로 메모리·계산 능력을 같이 쓰고, 서버 자체의 취약점으로 관리자 권한까지 뚫리면 계정 분리로 막지 못합니다. 더 강하게 나누려면 **별도의 작은 컴퓨터나 클라우드 서버**가 필요합니다.

### 2-2. 이 컴퓨터 안에서만 열기

프로그램은 `127.0.0.1`(이 컴퓨터 자신)의 8080번 문으로만 열었습니다. 즉 **다른 컴퓨터에서는 접속이 안 됩니다.** 내 PC에서 보려면 **SSH 터널**이라는 안전한 길을 열어서 봅니다.

```
ssh -N -L 8080:127.0.0.1:8080 -i <열쇠_파일> <웹_계정>@<서버_주소>
```

이 창을 열어 둔 채로 PC의 브라우저에서 `http://localhost:8080/`을 열면 됩니다. 창을 닫으면 길도 닫힙니다.

### 2-3. 컴퓨터가 켜지면 저절로 시작하게

`systemd`라는 서버 관리 기능에 **서비스**로 등록했습니다. 서비스 파일은 관리자 권한이 있어야 만들 수 있어서 비밀번호를 한 번 입력했습니다.

| 서비스 설정 | 하는 일 |
| --- | --- |
| 실행 계정 | 웹 전용 계정으로 실행 |
| 열 주소 | 이 컴퓨터 안(127.0.0.1)의 8080 |
| 죽으면 | **3초 뒤 자동으로 다시 시작** |
| 쓰기 허용 폴더 | **데이터 폴더만** (나머지는 읽기 전용) |
| 권한 올리기 금지 | 켬 |
| 메모리 상한 | 300MB |

프로그램을 강제로 끄는 시험을 여러 번 했고, **3초 안에 새 프로세스로 되살아나는 것을 확인했습니다.** 하지만 **컴퓨터를 실제로 껐다 켜는 시험은 하지 못했습니다**(서버가 다른 일도 하고 있어서 시간을 정해야 합니다).

## 3. 기능과 규칙

### 3-1. 승인제 가입

1. 방문자가 **아이디·비밀번호·닉네임·이름·이메일·전화번호**를 적어 가입을 신청합니다.
2. **관리자가 승인하기 전에는 로그인되지 않습니다.**
3. 글에는 **닉네임만** 표시되고, 이름·이메일·전화는 **관리자만** 볼 수 있습니다.
4. 거절하면 그 개인 정보는 삭제됩니다.

### 3-2. 비밀번호는 관리자도 못 봅니다

- 비밀번호는 **암호화(scrypt)** 해서 저장하므로, 관리자도 원래 비밀번호를 알 수 없습니다.
- 회원이 잊어버리면 **"비밀번호 초기화"** 로 임시 비밀번호를 만들어 전달하고, 그 회원은 로그인하면 **새 비밀번호로 바꿔야** 글을 쓸 수 있습니다.
- 모든 회원(관리자 포함)이 상단 메뉴에서 자기 비밀번호를 바꿀 수 있습니다.

### 3-3. 회원 관리(관리자 전용)

가입 승인·거절, 회원 목록, 비밀번호 초기화, **정지·정지 해제**, **삭제**를 할 수 있습니다.
- 삭제는 **그 회원의 아이디를 칸에 똑같이 입력해야** 됩니다(실수 방지).
- 삭제해도 그 회원이 쓴 **글과 댓글은 남습니다.**
- 관리자 계정은 초기화·정지·삭제가 되지 않습니다.

### 3-4. 글쓰기·수정·삭제

- 글은 **본인과 관리자**만 수정·삭제할 수 있습니다.
- 삭제는 **바로 지우지 않고 휴지통 폴더로 옮깁니다.** 화면에는 복구 버튼이 없어서, 되살리려면 서버에서 파일을 되돌려야 합니다.
- 글을 수정하면 "수정됨 시각"이 표시됩니다.

### 3-5. 파일 첨부

| | 관리자 | 일반 회원 |
| --- | --- | --- |
| 개수 | 제한 없음 | 글당 3개 |
| 파일당 크기 | 200MB | 5MB |
| 종류 | HTML 포함(실행 파일만 차단) | pdf·png·jpg·txt·md·docx·xlsx·pptx·zip |
| 종류 확인 | 이름 | **이름과 파일 첫 부분을 함께** 확인(가짜 확장자 차단) |

**HTML 첨부는 "화면에서 열기(격리)"로 열립니다.** 이때 브라우저의 **샌드박스**(격리 상자) 안에서 열려서, 그 페이지가 사이트 로그인이나 회원 정보에 접근할 수 없습니다. 일반 다운로드는 항상 내려받기만 됩니다.

**서버가 멈추지 않게 한 안전장치:** 파일을 **메모리를 거치지 않고 디스크로 바로 저장**하고, 디스크 여유가 20GB 아래로 줄면 업로드를 거부합니다. 완전 무제한은 서버가 멈출 수 있어 200MB 상한을 두었습니다. 그보다 큰 자료는 **구글 드라이브 등에 올리고 글에 링크**를 붙입니다.

### 3-6. 링크

본문과 댓글에 `https://…` 주소를 쓰면 **자동으로 눌리는 링크**가 되고 **새 탭**에서 열립니다. `javascript:` 같은 위험한 주소는 링크로 바뀌지 않습니다.

## 4. 어떻게 시험했나 (모두 임시 서버·임시 데이터로, 시험 뒤 삭제)

실제 서버에는 손대지 않고, **다른 문 번호로 임시 서버를 띄워** 시험했습니다. 기능을 하나 더할 때마다 이 순서를 반복했습니다.

1. 실제 데이터 폴더를 **백업**한다.
2. 새 프로그램을 **다른 이름으로 올려 문법을 검사**한다.
3. **임시 문 번호·임시 데이터**로 시험한다.
4. 통과하면 **교체하고 재시작**한다.

| 시험한 것 | 결과 |
| --- | --- |
| 기본 기능(목록·읽기·쓰기·로그인·로그아웃) | 통과 |
| 로그인 없이 쓰기, 위조 요청(CSRF), 가짜 로그인 쿠키 | **모두 차단** |
| 주소에 `../`를 넣어 프로그램·열쇠 파일 읽기 | 차단(404) |
| 글·검색창·이름 칸에 스크립트를 넣기 | 화면에서 실행되지 않음 |
| 로그인 5번 연속 실패 | **10분간 차단** |
| 아주 긴 글(30만 자) | 거부 |
| 승인 전 로그인·글쓰기 | 불가 |
| 일반 회원이 자료실에 쓰기·관리 화면 열기 | 차단(403) |
| 가입 양식에 관리자 권한을 끼워 넣기 | 무시됨 |
| 공개 화면과 다운로드에 이름·이메일·전화·아이디 노출 | 0건 |
| 회원 관리·댓글·수정·삭제·첨부·링크 | 각각 시험, 모두 통과 |
| **201MB 파일 올리기** | **거부**, 글과 임시 파일이 남지 않음, 서버 메모리 약 44MB |
| 속도(평소 / 계산 능력을 100% 쓰는 상황) | 목록 2ms / 12ms, 글 저장 2ms / 5ms, 동시 10명 최대 101ms |

**시험하다가 찾아서 고친 오류:** 글 머리말을 읽는 방식이 줄바꿈을 넘어 읽어서 모든 글이 자유게시판으로 분류되었습니다. 줄바꿈을 넘지 않게 고쳤습니다.

## 5. 평소 관리

### 5-1. 가입 승인과 관리자 지정

보통은 웹 화면의 **"회원 관리"** 에서 합니다. 서버에서 직접 하려면 다음 명령을 씁니다.

```
cd ~/<게시판_폴더> && python3 app.py --list-users
```

그 밖에 `--approve 아이디`, `--make-admin 아이디`가 있습니다. **관리자가 자기 비밀번호를 잊으면 웹으로는 복구할 길이 없어서**, 서버에서 쓸 복구 명령을 미리 만들어 두는 것이 좋습니다(아직 만들지 않았습니다).

### 5-2. 백업

글은 파일이라 **폴더를 통째로 복사**하면 됩니다. 단 이 폴더에는 **회원 개인 정보(`users.json`)와 로그인 서명 키(`secret.key`)** 가 함께 들어 있으므로 **외부에 공유하면 안 됩니다.**

### 5-3. 프로그램 고친 뒤 반영하기

반드시 **백업 → 임시 시험 → 교체** 순서로 합니다. 서버의 `data` 폴더를 덮어쓰면 회원과 글이 사라집니다.

### 5-4. 삭제한 글 되살리기

휴지통(`data/trash/`)의 `.md` 파일을 글 폴더로, 댓글 파일과 첨부 폴더도 제자리로 옮기면 됩니다. 어렵다면 복구 스크립트를 만드는 편이 안전합니다.

## 6. 막혔던 일과 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 홈페이지에 로그인·회원가입 메뉴가 없음 | 로그인 상태에 따라 메뉴를 넣는 기능이 홈 화면에는 없었음 | 서버가 홈 화면의 자리표시에 상태별 메뉴를 넣도록 수정 |
| 서비스 등록 스크립트가 "프로그램이 없다"며 중단 | 관리자 계정이 웹 계정의 폴더(700)를 읽지 못함 | 관리자 권한으로 파일 유무를 확인하도록 고쳐 다시 실행 |
| 속도 시험이 끝나지 않음 | 시험 스크립트가 서버 프로세스까지 기다림 | 기다릴 대상을 정확히 지정해 재실행 |
| 시험이 "실패"로 나왔는데 앱 문제가 아님 | 시험 기준(제목 단계)이 잘못되어 있었음 | 시험 기준을 고침(앱은 그대로) |
| 파일을 올리면 서버가 위험해질까 걱정 | 무제한 업로드는 메모리·디스크를 소진시킬 수 있음 | 파일당 200MB 상한, 디스크 여유 20GB 확인, 디스크로 바로 저장 |

## 7. 확인하지 못한 것 (그래서 아직 보증할 수 없는 것)

- **컴퓨터를 실제로 껐다 켠 뒤 서비스가 자동으로 시작되는지**
- 같은 서버의 **AI 에이전트가 일하는 동안의 실제 속도**(계산 능력 100% 흉내 시험만 했음)
- **집 안 와이파이의 다른 기기에서의 접속**(이 글의 서버는 자기 컴퓨터 안에서만 열었음)
- **인터넷 공개**: 하지 않았습니다. 하려면 먼저 `https`, 쿠키의 `Secure` 설정, 응답 헤더의 서버 이름 숨기기, 개인 정보 안내 문구, 로그인 실패 제한을 파일로 저장하기(지금은 메모리에만 있어 서버를 다시 시작하면 사라짐)가 필요합니다. 이메일·전화 인증이 **없다**는 점도 알아 두어야 합니다.
- 글이 **수천 개** 넘었을 때의 속도(20개에서 목록 12ms까지만 확인)
- 회원의 개인 정보를 다루는 데 필요한 **법적 의무**
